Production Typesense (ECS Fargate) — what GitHub Actions does NOT do for you yet
=================================================================================

prod-backend-deploy.yml only rolls your Django image on the existing web/worker task definitions.
Typesense is a separate container/service. Use one of these patterns:

A) Typesense Cloud (simplest ops)
   - Create a cluster in Typesense Cloud; set on web + worker task definitions:
     TYPESENSE_HOST, TYPESENSE_PORT, TYPESENSE_PROTOCOL=https (if applicable),
     TYPESENSE_API_KEY, TYPESENSE_COLLECTION_ALIAS=classes_live
     TYPESENSE_AUTO_BOOTSTRAP=true (optional; full rebuild if index empty — OK on Cloud with persistence)

B) Self-hosted on ECS (this repo adds typesense-ecs-deploy.yml for image bumps)
   1) VPC: security group for Typesense allowing TCP 8108 from web/worker security groups only.
   2) Create an ECS task definition with ONE container named exactly: typesense
      Image: typesense/typesense:26.0 (or match typesense-ecs-deploy.yml default)
      Port mapping: 8108
      Essential: true
      Environment:
        TYPESENSE_DATA_DIR=/data
        TYPESENSE_API_KEY=<strong secret — prefer AWS Secrets Manager + secretOptions>
        TYPESENSE_ENABLE_CORS=true
      For durable index across task replacements: mount Amazon EFS at /data (recommended).
      Without EFS, disk is ephemeral — Django’s bootstrap task will repopulate when empty (slow on large catalogs).
   3) Create ECS service (Fargate, awsvpc) on private subnets; optional AWS Cloud Map for stable DNS
      (e.g. typesense.internal) and set TYPESENSE_HOST to that hostname on web/worker.
      Alternatively use the service’s internal load balancer / NLB DNS name.
   4) On BOTH web and worker ECS task definitions, add the same Django env vars as staging:
      TYPESENSE_HOST, TYPESENSE_PORT, TYPESENSE_PROTOCOL, TYPESENSE_API_KEY,
      TYPESENSE_COLLECTION_ALIAS, TYPESENSE_AUTO_BOOTSTRAP
   5) To upgrade Typesense image later: Actions → “Deploy Typesense (ECS)” → workflow_dispatch.

Staging (EC2) — automated in staging-deploy.yml
=================================================
- Add GitHub secret: TYPESENSE_API_KEY (required for the Typesense container).
- Deploy workflow starts container `typesense` on Docker network classeasily-net with volume classeasily-typesense-data.
- Django uses TYPESENSE_HOST=typesense (Docker DNS).

Rotating TYPESENSE_API_KEY on staging
=====================================
After changing the GitHub secret, remove the old container once so it picks up the new env:
  docker rm -f typesense
then redeploy (workflow recreates it).

Production Fargate reference (us-east-2, account 459929160817)
===============================================================
Stable DNS for Django: TYPESENSE_HOST=typesense.classeasily.local (Cloud Map namespace classeasily.local).

- ECS cluster/service: classeasily-prod-cluster / classeasily-prod-typesense-service
- Task definition family: classeasily-prod-typesense-task (container name must stay "typesense" for typesense-ecs-deploy.yml)
- EFS (encrypted, /data): fs-022624328107e5b42
- Typesense task SG: sg-0bb7a671830e90e1a (8108 from app sg-0759107194bc02c3e)
- EFS SG: sg-0641f7aa7e140c73d (NFS 2049 from typesense task SG)
- Cloud Map: namespace ns-o2sbtemvb76z3uzc; discovery service srv-piz5i5qavls437xe
- IAM task role (EFS): classeasily-prod-typesense-task-role (+ inline policy on file system above)
- Prod Django env secret classeasily/prod/env includes TYPESENSE_* keys; web/worker task defs reference them via secrets

prod-backend-deploy.yml sets ECS_WEB_HEALTH_CHECK_GRACE_PERIOD_SECONDS (default 900) on classeasily-prod-web-service so the ALB does not fail tasks during long web startup (migrate + Typesense full reindex per deploy). Raise ECS_WEB_HEALTH_CHECK_GRACE_PERIOD_SECONDS in the workflow if the catalog grows.

Ops helpers in deployment/ecs/
- merge_prod_typesense_env.py — merge TYPESENSE_* into classeasily/prod/env (generates API key only if missing)
- patch_ecs_prod_django_typesense_secrets.py web|worker — register new task revision with TYPESENSE_* ASM refs and force deploy
- classeasily-prod-typesense-task-definition.json — baseline task JSON used for initial register-task-definition

Verify from AWS (no curl needed on a laptop): CloudWatch log group /ecs/classeasily-prod-typesense should show "listening on port 8108".
From a task inside the VPC (ECS Exec, bastion, or one-off Fargate): curl http://typesense.classeasily.local:8108/health

Optional before cutover: run manage.py reindex_classes from a container that can reach Typesense to pre-warm.
Push backend Redis namespacing + any Django fixes to prod so Valkey keys for Typesense locks/cache stay env-scoped.
